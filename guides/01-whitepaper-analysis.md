# 📄 Guide 01 — How to Analyze a Crypto Whitepaper

A whitepaper is the founding document of any crypto project. If there's no whitepaper — or it's vague — that's your first red flag.

---

## What Is a Whitepaper?

A whitepaper is a technical document that explains:
- **What** problem the project solves
- **How** the technology works
- **Why** a token is needed
- **Who** is building it and when

---

## The 6 Things to Look For

### 1. 🎯 Problem Statement
- Is the problem real and clearly defined?
- Is blockchain actually necessary to solve it, or could a regular database do it?
- Red flag: vague language like "revolutionizing the future of finance"

### 2. 🔧 Technical Solution
- Does the technical explanation make sense?
- Is there a working product or just a concept?
- Is the code open-source? (Check GitHub activity)
- Red flag: no GitHub repo, or a repo with no commits in 6+ months

### 3. 💰 Token Utility
- Why does this project need a token?
- What can you actually DO with the token? (pay fees, vote, stake?)
- Red flag: the token exists only to raise money, with no real utility

### 4. 🗓️ Roadmap
- Are milestones specific with dates?
- Have past milestones been hit?
- Red flag: roadmap is all future promises with nothing delivered yet

### 5. 👥 Team
- Are team members named and verifiable on LinkedIn?
- Do they have relevant experience?
- Red flag: anonymous team with no track record

### 6. 📚 References & Citations
- Does the whitepaper cite real research?
- Are the claims backed by data?
- Red flag: no citations, inflated numbers with no source

---

## Where to Find Whitepapers

- Project's official website (usually under "Docs" or "About")
- [CoinMarketCap](https://coinmarketcap.com) — each coin's page links to it
- [CoinGecko](https://coingecko.com) — same
- GitHub — look for a `whitepaper.pdf` in the repo

---

## ✅ Whitepaper Checklist

- [ ] Problem is clearly defined and real
- [ ] Blockchain is actually necessary for the solution
- [ ] Token has clear utility beyond fundraising
- [ ] Team is named and verifiable
- [ ] Roadmap has specific, trackable milestones
- [ ] Past milestones have been delivered
- [ ] Code is open-source and actively maintained
- [ ] No excessive jargon hiding a lack of substance

---

*If it reads like a sales pitch more than a technical document — trust your gut.*
